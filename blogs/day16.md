前回は、Embeddingが文章をベクトルに変換し、意味の近い文章を探すための仕組みだと学びました。今回は実際に`bge-m3`を動かし、入力した文章に近い候補をスコア付きで検索します。

最初にAPIの結果をそのまま表示すると、ターミナルが小数の列で埋まりました。概念として聞いていた「ベクトル」が、本当に大量の数字として返ってくるのを見るとなかなかの迫力です。

## 今日やったこと

### 文章が1024個の数字になった

まず、OllamaのEmbedding APIである`/api/embed`へ文章を1つ送りました。

```bash
curl http://localhost:11434/api/embed \
  -d '{
    "model": "bge-m3",
    "input": "猫がソファで眠っています"
  }'
```

返ってきたJSONには、次のような小数が延々と並んでいました。

```text
{"model":"bge-m3","embeddings":[[-0.029028015,0.0044517843,-0.05248526,...]]}
```

この数字を一つずつ読むわけではありません。配列の長さだけを`jq`で数えてみます。

```bash
curl -s http://localhost:11434/api/embed \
  -d '{
    "model": "bge-m3",
    "input": "猫がソファで眠っています"
  }' \
  | jq '.embeddings[0] | length'
```

結果は`1024`でした。今回使った`bge-m3`は、1つの文章を1024個の数値、つまり1024次元のベクトルとして表現していました。

### 10文章をまとめてベクトル化する

次に、動物、料理、パソコンなどを題材にした10文章をPythonのリストへ用意しました。`embed()`関数からOllamaを呼び、10文章をまとめてベクトル化します。

```python
def embed(texts):
    """文章をOllamaへ送り、Embeddingの一覧を取得する。"""

    # PythonのデータをJSONへ変換し、APIへ送れるバイト列にする
    data = json.dumps({
        "model": EMBED_MODEL,
        "input": texts,
    }).encode("utf-8")

    request = urllib.request.Request(
        OLLAMA_EMBED_URL,
        data=data,
        headers={"Content-Type": "application/json"},
    )

    with urllib.request.urlopen(request) as response:
        result = json.load(response)

    return result["embeddings"]
```

実行すると、文章数は10、各ベクトルの次元数は1024になりました。入力した文章ごとに、1つのベクトルが返ってきたことを確認できました。

ここで、関数の先頭にある`"""..."""`についても確認しました。これはdocstringと呼ばれ、関数全体が何をするものか説明する文章です。関数内の`#`コメントは、個々の処理の目的や流れを補足します。

### コサイン類似度で向きの近さを測る

質問文と保存済み文章の近さを比べるため、コサイン類似度を計算する関数を作りました。

```python
def cosine_similarity(vector_a, vector_b):
    """2つのベクトルの向きがどれくらい近いか計算する。"""

    dot_product = sum(
        a * b for a, b in zip(vector_a, vector_b)
    )

    magnitude_a = math.sqrt(sum(a * a for a in vector_a))
    magnitude_b = math.sqrt(sum(b * b for b in vector_b))

    return dot_product / (magnitude_a * magnitude_b)
```

ざっくり言えば、2つのベクトルの内積を、それぞれのベクトルの大きさで割っています。これにより、大きさではなく向いている方向の近さを比べられます。

1024個の数字を自分で追う必要はありません。Pythonで質問文と10文章を1件ずつ比較し、スコアの高い順に並べました。

### 検索結果は良い感じ、でも条件判定ではない

「今日は忙しいので短時間で作れる料理を知りたい」と入力した結果は、次のようになりました。

```text
1. 0.8411  忙しい日は短時間で作れる料理が便利です。
2. 0.6270  休日に時間をかけてカレーを煮込みます。
3. 0.5338  キャベツを使った濃い味の炒め物を作ります。
4. 0.5134  パソコンを使ってPythonを勉強しています。
5. 0.4539  電車に乗って職場へ向かいます。
6. 0.4434  雨の日は家で本を読んで過ごします。
7. 0.4003  スマートフォンは多くの人が持つ身近な端末です。
8. 0.3850  動物園には珍しい動物がたくさんいます。
9. 0.3646  猫がソファの上で昼寝をしています。
10. 0.3427  犬が公園で元気に走っています。
```

入力とほぼ同じ意味の文章が`0.8411`で1位になり、料理の文章が上位3件にまとまりました。

一方、2位は「休日に時間をかけてカレーを煮込みます」です。「忙しい」と「休日」、「短時間」と「時間をかける」はむしろ反対ですが、料理と時間に関する文章としては近いと判定されたのかなと思います。

つまり、ベクトル検索は条件を厳密にチェックして候補を除外する仕組みではありません。文章全体の意味が近い候補を順位付けします。スコアも、一定以上なら必ず正解というより、同じ検索内で順位や差を見るものだと理解しました。
