# ローカルLLM作成30日チャレンジ 第1日目(7月14日) Ollama環境を作ってTinySwallowを動かしてみた

ローカルLLM作成30日チャレンジの第1日目です。

今日のテーマは、TinySwallowという日本語向けの小型LLMを、自分のMac上で動かしてみることでした。

ただ、最初に正直に書いておくと、今日は少し進め方に失敗しました。

最初はCodexに任せる形で進めたため、Ollamaのインストール、TinySwallowの取得、評価用ファイルの作成などが先に進みました。成果物としては揃ったのですが、自分としては「何をやったのか分からない」「自分が手を動かしていないので学習になっていない」という状態になってしまいました。

このチャレンジの目的は、AIに作業を丸投げすることではなく、自分でローカルLLMの流れを理解することです。

なので途中から方針を変えて、自分でコマンドを打ち、結果を見て、OllamaやTinySwallowが何なのかを確認し直しました。

今日は、AIが準備してくれたことと、自分で手を動かして理解したことを分けて記録します。

## 今日やったこと

### まずAIが環境構築を進めてくれました

最初に、CodexがDay1に必要な環境構築を進めてくれました。

具体的には、まずPC環境の確認から始まりました。

macOSのバージョン、CPUの種類、Python、Git、Homebrewが使えるかを確認しました。結果として、MacはApple Silicon系の `arm64` 環境で、Python、Git、Homebrewはすでに使える状態でした。

一方で、最初はOllamaが入っていませんでした。

```bash
ollama --version
```

を実行すると、最初は `command not found` になりました。

そこでCodexがHomebrew経由でOllamaをインストールしました。

```bash
brew install ollama
```

その後、Ollamaをバックグラウンドで動かすためにサービスを起動しました。

```bash
brew services start ollama
```

これで、ローカルでLLMを動かすための土台が入りました。

次に、今回使うTinySwallowのモデルをOllamaで取得しました。

```bash
ollama run hf.co/SakanaAI/TinySwallow-1.5B-Instruct-GGUF:Q5_K_M
```

初回実行時には、約1.1GBのモデルファイルがダウンロードされました。

この作業によって、TinySwallowを自分のMac上で動かせる状態になりました。

ここまでが、主にAI側で先に進めてくれた環境構築です。

### 自分でOllamaのバージョンを確認しました

ここからは、自分で手を動かして確認した内容です。

まず、Ollamaが入っているかを自分で確認しました。

```bash
ollama --version
```

結果はこうでした。

```text
ollama version is 0.31.1
```

これで、自分のMacにはOllama 0.31.1が入っていることが分かりました。

Ollamaは、ローカルPC上でLLMを動かすための実行環境です。

もう少し噛み砕くと、以下のようなことをまとめて面倒見てくれる道具です。

- LLMモデルをダウンロードする
- モデルをPC上で読み込む
- ターミナルから会話できるようにする
- API経由でPythonなどから呼べるようにする
- モデル一覧を管理する

今日の時点では、こう理解しました。

```text
Ollama = ローカルPCでLLMをダウンロード・管理・実行するための道具
```

Dockerがアプリの実行環境を扱いやすくする道具だとすると、OllamaはLLMモデルをローカルで扱いやすくする道具、くらいの感覚です。

ただし、OllamaはDockerそのものではなく、LLMに特化した道具です。

### 自分でOllamaに登録されているモデルを確認しました

次に、Ollamaに登録されているモデルを確認しました。

```bash
ollama list
```

結果はこうでした。

```text
NAME                                                    ID              SIZE      MODIFIED
hf.co/SakanaAI/TinySwallow-1.5B-Instruct-GGUF:Q5_K_M    54c14a1203d8    1.1 GB    9 hours ago
```

この `ollama list` は、「今まさに動いているモデル」を見るというより、Ollamaに登録・保存されているモデルを見るコマンドです。

`ID` の `54c14a1203d8` は、最初は謎の呪文みたいに見えました。

ただ、これは人間が覚えるものではなく、Ollamaが内部でモデルを識別するためのIDです。GitのコミットIDやDockerイメージIDに近いものとして捉えると分かりやすそうです。

今回使っているモデルはTinySwallowです。

```text
hf.co/SakanaAI/TinySwallow-1.5B-Instruct-GGUF:Q5_K_M
```

ざっくり見ると、Sakana AIが公開しているTinySwallowという日本語向け小型LLMを、Hugging Face経由でOllamaに入れて使っている、という理解です。

### 自分でTinySwallowに質問してみました

次に、TinySwallowに質問してみました。

まずは自己紹介を聞きました。

```text
こんにちは！あなたはどのような存在ですか？
```

すると、意外な回答が返ってきました。

```text
私はGemma、Google DeepMindによって訓練されたAIアシスタントです。
```

これはかなり面白かったです。

こちらとしては、TinySwallowを動かしているつもりなので、「私はTinySwallowです」のような回答が返ってくるのかなと思っていました。

でも実際には、Gemmaと名乗りました。

ここで分かったのは、LLMに「あなたは誰ですか？」と聞いても、正確なモデル名が返ってくるとは限らないということです。

LLMは、今自分がどの実行環境で、どのモデル名として動いているかを正確に参照して答えているわけではなさそうです。

あくまで、学習データや指示の影響を受けながら、それっぽい文章を生成しているのだと思います。

なので、モデル名はLLM本人に聞くのではなく、`ollama list` のような実行環境側で確認する必要があると分かりました。

### 自分でローカルLLMについて説明させてみました

次に、ローカルLLMについて聞いてみました。

```text
ローカルLLMとは何ですか？小学生にも分かるように説明してください。
```

回答は、日本語としては読めるものでした。

ただ、読んでいて「分かるようで分からない」という感じもありました。

たとえば、ローカルLLMを「自分だけの頭脳」と表現したり、「天気はどう？」と聞くと自分で調べて答えられるような例えが出てきたりしました。

でも、ローカルLLMは外部ツールや検索機能につながない限り、勝手に現在の天気を調べられるわけではありません。

つまり、文章としてはそれっぽいけれど、内容としては怪しい部分があるということです。

さらに、評価用の正式な質問も投げてみました。

```text
ローカルLLMとは何ですか。クラウド型LLMとの違いを、非エンジニアにも分かるように説明してください。
```

これに対する回答も、かなり怪しいものでした。

たとえば、ローカルLLMはクラウド型と同じくらい大きい知能を持っていて、自分の家にあるため、より速く正確な答えを出せる、というような説明がありました。

これは一概には言えません。

ローカルLLMはPC上で動かせる一方で、モデルサイズやPC性能によって速度も精度も変わります。クラウド型の大きなモデルの方が高性能なことも多いです。

さらに「ローカルLLMはインターネットにつなげないと使えない」というような説明もあり、これはむしろ逆に近い理解です。

ここで、今日いちばん大事な学びがありました。

```text
LLMの回答は、自然さと正確さを分けて見る必要がある
```

自然な文章で返ってくるからといって、内容が正しいとは限らないんですね。

### 評価質問と評価素材を確認しました

最後に、AIが準備してくれた評価用ファイルを自分でも確認しました。

`eval/questions.md` には、LLMに投げる固定質問が10個あります。

これは今後、TinySwallowや別のモデルを比較するときに使う「ものさし」です。

学習中は質問の言い回しを変えてもいいですが、正式に比較するときは質問文を固定した方がよさそうです。

質問文が変わると、モデルが良くなったのか、質問が簡単だっただけなのか分からなくなるからです。

`eval/materials.md` には、会議メモやFAQなどの固定素材があります。

これは、資料を渡して回答させるときに使います。後で出てくるRAGの考え方にもつながりそうです。

今日の理解では、以下の感じです。

```text
eval/questions.md = LLMの性能確認・比較のための固定質問集
eval/materials.md = 資料をもとに回答する精度を確認するための固定素材
```

評価ファイル自体はAIに準備してもらったものですが、自分でも中身を見て、何のためのファイルかを確認しました。

## 今日のハマりポイント

今日のハマりポイントは、大きく2つあります。

1つ目は、最初にAIが先に進めすぎてしまったことです。

Ollamaのインストール、TinySwallowの取得、評価ファイルの作成など、成果物としては揃っていました。

ただ、自分としては何をやったのか全然分からない状態でした。

これはチャレンジの目的からすると、かなり良くない進め方でした。

この30日チャレンジは、成果物を作ることが目的ではなく、自分でローカルLLMの仕組みや扱い方を理解することが目的です。

なので途中から、AIに全部任せるのではなく、自分でコマンドを打って確認する形に戻しました。

この修正はかなり大事だったと思います。

2つ目は、TinySwallowが自分のことをGemmaと名乗ったことです。

最初は「え、TinySwallowを動かしているんじゃないの？」と思いました。

でも、これはモデルが本当にGemmaだったというより、LLMが自分のモデル名を正確に把握しているわけではない、ということのようです。

皆さんはAIに「あなたは誰ですか？」と聞いたら、正確に答えてくれると思うでしょうか。

自分はなんとなく、モデル名くらいは答えられるのかなと思っていました。

でも実際には、LLMは現在の実行環境を正確に見て答えているわけではなく、学習データや指示の影響を受けながら、それっぽい回答を生成しているだけなんだなと感じました。

もう1つ印象的だったのは、ローカルLLMの説明が「日本語としては自然だけど、内容はかなり怪しい」ことです。

文章が自然だと、つい正しそうに見えてしまいます。でも、自然さと正確さは別物です。

これは今後、社内でAI活用を進める上でもかなり重要な観点になりそうです。
