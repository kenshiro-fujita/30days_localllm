# ローカルLLM作成30日チャレンジ Day12(8月1日) JSONで回答させて構造化出力を試す

ローカルLLM作成30日チャレンジのDay12です。

前回は、TinySwallowの回答を少しずつ表示するストリーミングを試しました。今回は、回答をただの文章ではなく、Pythonから扱いやすいJSON形式で返してもらいます。

JSONで返すように指示すれば素直に返してくれるのかと思っていましたが、TinySwallowはかなり自由でした。

## 今日やったこと

### JSONをPythonで読み込む

まずはLLMを呼ぶ前に、JSON形式の文字列をPythonで扱う方法を確認しました。

```bash
python -c 'import json; text = "{\"category\": \"質問\", \"sentiment\": \"中立\"}"; result = json.loads(text); print(result); print(result["category"])'
```

実行結果は次のとおりです。

```text
{'category': '質問', 'sentiment': '中立'}
質問
```

APIから届いたJSONは最初は文字列です。`json.loads()` を使うとPythonの辞書へ変換され、`result["category"]` のように必要な値を取り出せます。

次に、値をダブルクォートで囲んでいない、不正なJSONも試しました。

```text
json.decoder.JSONDecodeError: Expecting value: line 1 column 14 (char 13)
```

形式が壊れている場合は `JSONDecodeError` になることを、先に小さな例で確認できました。

### 文章分類のスクリプトを作る

Day12の成果物として、`src/json_classifier.py` を自分で作成しました。コードはCodexに一部分ずつ案内してもらい、自分でファイルへ追加して実行しています。

最初は、入力した文章を「質問・依頼・感想・その他」のどれかに分類し、次の形式で返すようsystem promptへ指定しました。

```json
{"category": "質問"}
```

ところが最初の実行では、指定していない分類と説明文が返ってきました。

```text
{"category": "情報提供"}
{"message": "申し訳ありませんが、私は現在のカレンダー情報を持っていないため..."}
```

JSONらしきものは出ていますが、JSONオブジェクトが2つ連続しているので、全体を1つのJSONとして解析できません。

同じ入力でもう一度実行すると、今度はきれいなJSONが返りました。

```text
{"category":"質問"}
```

同じ指示でも毎回同じ結果になるとは限らないことが、さっそく分かりました。

### Markdownまで付けて返してくる

次に「このアプリはとても使いやすかったです」と入力しました。期待する分類は「感想」です。

返ってきた内容は、分類自体は合っていました。

````text
```json
{
   "category": "感想"
}
```
````

しかし、JSONがMarkdownのコードブロックで囲まれ、その後ろにも英語と日本語の説明が続きました。そのため `json.loads()` は、先頭のバッククォートをJSONとして解釈できず失敗しました。

system promptへ「Markdownを使わない」「JSONの前後に説明を書かない」と明記し、`temperature=0` にしても結果は同じでした。しかもTinySwallowは、Markdownのコードブロックを使った直後に「Markdownのコードブロックを使わずに出力した」と説明していました。めっちゃ不安定です。

### API側でJSON形式を指定する

プロンプトだけでは安定しなかったため、API呼び出しへ次の指定を追加しました。

```python
response_format={"type": "json_object"},
```

同じ文章をもう一度入力すると、今度は純粋なJSONが返りました。

```text
{"category":"感想"}
```

プロンプトはモデルへのお願いですが、`response_format` はAPI側から出力形式を制限する指定です。今回の実験では、これを追加した後はMarkdownや説明文が混ざらなくなりました。

### 分類・要約・感情をまとめて返す

最後に、回答へ次の3項目を含めるよう拡張しました。

- `category`: 質問・依頼・感想・その他
- `summary`: 入力内容の短い要約
- `sentiment`: 肯定的・否定的・中立

「アップデート後から起動が遅くなって、とても困っています」と入力した結果はこちらです。

```json
{"category": "質問", "summary": "アップデート後から起動が遅くなった。", "sentiment": "否定的"}
```

JSON、要約、感情分類は問題なさそうです。一方、質問している文章ではないので、`category` の「質問」は少し不自然です。

別の肯定的な感想文では、次の分類が返りました。

```json
{"category": "質問・依頼", "summary": "新しい検索機能のおかげで、目的の資料をすぐに見つけられた", "sentiment": "肯定的"}
```

`質問・依頼` は許可した選択肢にありません。そこでPython側にも、分類名と感情が想定した候補に含まれるかを確認する処理を入れました。この出力はJSONとしては正しいものの、プログラム側では「想定外の分類」と検出できました。

分類基準をsystem promptへ追加すると複合ラベルは出なくなりましたが、今度は感想文を「質問」と分類しました。形式を安定させることと、内容を正しくすることは別の課題のようです。

## 今日のハマりポイント

一番のハマりは、JSONで返すように何度指示しても、TinySwallowがコードブロックや説明文を付けてきたことです。

「Markdownを使わない」と明記してもMarkdownを使い、その直後にルールを守ったと説明する出力までありました。プロンプトを詳しくすれば必ず従うわけではなく、形式を安定させるにはAPI側の制約も必要だと分かりました。

途中では、systemメッセージを置き換える範囲についてCodexの案内が分かりにくく、辞書の外側に余分な波括弧が残りました。

```text
TypeError: cannot use 'dict' as a set element (unhashable type: 'dict')
```

行番号付きでコードを表示して確認したところ、Pythonが外側の波括弧を集合として解釈していたことが原因でした。余分な波括弧を削除して解消しています。

## 今日の感想

今日は、JSONとして正しいことと、分類内容が正しいことは別だと理解できました。

JSONとして正しいかは、PythonやLLMの出力形式の話です。一方、分類内容が正しいかはLLMの回答内容の問題です。きれいなJSONが返ってくると成功したように見えますが、中身まで正しいとは限りません。

`json.loads()` で形式を確認し、必要なキーと値をPython側で検証し、さらに分類内容を人間や評価データで確認する必要があります。構造化出力にするとプログラムから扱いやすくなりますが、LLMの判断をそのまま信用してよいわけではない、というのが今日の大きな学びでした。

次は、これまで作った処理を組み合わせて、日本語文章を要約・改善・分類するミニアプリへ進みます。
