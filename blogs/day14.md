### まず`OpenAI`が何を指すのか整理する

コードには、次のimportがあります。

```python
from openai import OpenAI
```

ここで読み込んでいる`OpenAI`は、APIそのものでもOpenAIのLLMでもありません。OpenAI公式のPythonライブラリが提供する、APIへリクエストを送るためのクライアントです。

APIクライアントは、送信するデータを決められた形に組み立てて接続先へ送り、返ってきたデータをPythonから扱いやすくする道具です。

### クライアントの接続先をOllamaにする

読み込んだクライアントを、次のコードで準備しています。

```python
client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",
)
```

`OpenAI`クライアントは通常OpenAIのサービスへの接続に使われますが、`base_url`で接続先を変更できます。今回は`localhost`を指定しているので、実際の接続先はOpenAIのサーバーではなく、自分のPCで起動しているOllamaです。

ここまでを整理すると、次の関係です。

```text
openai Pythonライブラリ
  ↓ OpenAIクライアントを提供
Pythonアプリ
  ↓ base_urlで指定した場所へ送信
自分のPC上のOllama
```

### ここで初めて「OpenAI互換API」を理解する

APIは、プログラム同士が決められた方法で情報を受け渡すための窓口です。接続先のURL、送る項目、返ってくるデータの形などに決まりがあります。

OpenAIは、`model`や`messages`を送って回答を受け取るAPI形式を提供しています。Ollamaもその呼び出し方の一部へ対応しているため、OpenAI公式のPythonクライアントからOllamaを呼び出せます。このように、OpenAIと似た決まりで呼び出せることを「OpenAI互換」と呼びます。

つまり、OpenAI互換なのはAPIの呼び出し方です。OpenAIのモデルやサーバーを使っているという意味ではありません。自分としては、「OpenAI風の注文票を使って、ローカルのOllamaへ注文している」という説明が一番分かりやすかったです。

全体の流れは次のように整理しました。

```text
ユーザー
  ↓ 入力
Pythonアプリ
  ↓ HTTPリクエスト
OllamaのAPI受付窓口
  ↓ モデルを実行
TinySwallow
  ↓ 回答
Ollama
  ↓ APIレスポンス
Pythonアプリ
  ↓ 出力を検証
ユーザーへ表示
```

この内容は、`notes/day14_api_summary.md`へまとめました。

## 今日のハマりポイント

### Codexが用語を説明せずに使っていた

最初のまとめでは、Codexが「OpenAI互換API」という用語を、構成要素の一つとしていきなり出していました。しかし、`from openai import OpenAI`の`OpenAI`が何なのか、APIクライアントとAPIはどう違うのかを先に説明していませんでした。

そのため、OpenAIのライブラリ、OpenAI互換API、Ollama、TinySwallowの関係が分かりにくい説明になっていました。これはCodex側の説明順の問題です。

改めて、APIクライアント、接続先、APIの呼び出し形式、実行モデルの順で整理しました。`OpenAI`はリクエストを送るクライアントで、接続先は`base_url`によってOllamaになり、実際に文章を生成するのはTinySwallowです。そのうえで、OllamaがOpenAIと似た形式を受け付けることを「OpenAI互換」と呼びます。

`base_url`がどこを指しているかを見ると、実際の通信先を判断できます。コードのライブラリ名だけで、どのサービスへ送信しているかを決めつけないことも大切だと思います。

### Codexの操作案内が分かりにくかった

まとめファイルをnanoで保存するとき、Codexから`Ctrl+O`と案内されました。しかし、アルファベットのOなのか数字の0なのかが明記されておらず、自分は数字の0を押していました。

さらに、部分ごとの貼り付け案内に説明文が混ざり、まとめファイルの先頭へ不要な文章が入りました。最終的には、Codexにファイル全文を出してもらい、自分で内容を置き換えました。

これは自分の操作ミスというより、Codex側の表記と貼り付け手順が分かりにくかったことが原因です。ターミナル操作を案内するなら、「アルファベットのO」のように曖昧さをなくし、貼り付ける本文と操作説明を明確に分ける必要があります。
