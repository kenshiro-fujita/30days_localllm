ローカルLLM作成30日チャレンジのDay11です。

前回は、会話履歴を持つCLIを作りました。今回は、TinySwallowの回答を最後にまとめて表示するのではなく、生成されたところから少しずつ表示するCLIを作ります。

普段使っているAIでは自然に見かける表示ですが、自分で実装してみると、完成した回答と生成途中の断片では扱い方が違うことが分かりました。

## 今日やったこと

### 一括表示のコードを確認

まず、Day9で作った `src/ask_tinyswallow.py` を確認しました。このスクリプトでは、TinySwallowが回答を最後まで生成した後、次の処理で回答全体を表示します。

```python
print(response.choices[0].message.content)
```

実際に長めの回答を求めると、生成中は何も表示されず、完成後に回答全体が一括で現れました。

### ストリーミング版を作成

Day11の成果物として `src/stream_chat.py` を作りました。OpenAI互換APIの呼び出しに `stream=True` を追加します。

```python
stream = client.chat.completions.create(
    model="hf.co/SakanaAI/TinySwallow-1.5B-Instruct-GGUF:Q5_K_M",
    messages=[
        {
            "role": "user",
            "content": question,
        }
    ],
    stream=True,
)
```

返ってくる回答は、完成した一つの文章ではありません。`for` ループで `chunk` と呼ばれる断片を順番に取り出し、その中の `delta.content` を表示します。

```python
for chunk in stream:
    content = chunk.choices[0].delta.content

    if content is not None:
        print(content, end="", flush=True)
```

`end=""` は断片ごとの余計な改行を防ぐ指定で、`flush=True` は届いた文章をためずにすぐ表示する指定です。

### 本当に断片で届いているか確認

最初に実行したときは、回答全体が一括で表示されたように見えました。そこでCodexの案内で、届いた `chunk` を一つずつ確認できる表示へ一時的に変更しました。

```text
[chunk: 'ロ']
[chunk: 'ーカ']
[chunk: 'ル']
[chunk: 'LL']
[chunk: 'M']
```

結果はご覧の通り、回答がかなり細かい断片に分かれて届いていました。ただ、この確認表示は細かすぎて、自分としては「わけわからん事になった」という状態でした。確認用コードの見せ方はCodex側が分かりやすく案内できていなかったと思います。

通常の表示へ戻してあらためて画面を見ると、回答が逐次少しずつ表示されていることを確認できました。

### 一括表示と体感速度を比較

一括表示版とストリーミング版へ、どちらも長めの回答になる同じ質問を送りました。

一括表示では、すべての回答をLLMが出し尽くしてから表示されます。一方、ストリーミング表示では、回答の断片が出てき次第表示されます。

回答全体を作る時間が短くなったわけではありませんが、逐次表示のほうが動いている感があり、待ち時間の体感はよくなりました。

### エラー処理を追加

最後に、接続失敗、APIエラー、ユーザーによる中断を扱う例外処理を追加しました。

```python
except APIConnectionError:
    print("Ollamaに接続できませんでした。Ollamaが起動しているか確認してください。")

except APIError as error:
    print(f"APIの処理中にエラーが発生しました: {error}")

except KeyboardInterrupt:
    print("\n処理を中断しました。")
```

長い回答を生成している途中で `Ctrl+C` を押すと、次のように終了できました。

```text
ローカルLLM (Local Large Language Model)は、クラウドではなく、
自分のコンピュータやスマートフォンなどのデバイス上で動作する
大規模言語モデルのことです。これにより、AIの能力を^C
処理を中断しました。
```

処理中に終了したくなった場合も、長いエラー表示を出さずに終われるようになりました。

## 今日のハマりポイント

最初のハマりは、ストリーミング版でも一括表示されたように見えたことです。

そこで断片を一つずつ表示してみると、APIからは正しく多数の `chunk` が届いていました。仕組みを確認する表示と、人間が回答を読むための表示は別に考える必要がありました。

もう一つは、TinySwallowへ「ローカルLLMってなんですか？」と聞いたところ、「ロケーション・オンリーのLarge Language Model」の略だという、もっともらしい誤情報が返ってきたことです。

ストリーミングは表示方法を変える機能で、モデルの回答品質を改善する機能ではありません。回答が早く見え始めても、内容の正しさは別に確認する必要があります。
