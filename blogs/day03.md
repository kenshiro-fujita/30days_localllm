# ローカルLLM作成30日チャレンジ 第3日目(7月16日) temperatureってなんぞ？

ローカルLLM作成30日チャレンジの第3日目です。

昨日はトークンについて触りました。

LLMは文字ではなくトークンで文章を扱っていて、日本語は見た目よりトークン数が重くなることがある、という話でした。

今日はそこから少し進んで、LLMの出力がどう変わるのかを見ていきました。

テーマは「生成パラメータ」です。

特に今日は `temperature` を中心に触りました。

`temperature` は、ChatGPTなどを触っているとなんとなく見かける単語です。ただ、実際に何が変わるのかは、試してみないと少し分かりにくいところがあります。

今日はTinySwallowで `temperature` を変えながら、同じ質問にどんな回答が返ってくるのかを見ていきました。

## 今日やったこと

### まずtemperatureとは何かを確認しました

最初に、Codexから `temperature` の説明を受けました。

ざっくり言うと、`temperature` はLLMの出力のランダムさを調整する設定です。

```text
temperature 低め = 安定、無難、再現性が高め
temperature 高め = 多様、自由、冒険的
```

ただし、ここで大事なのは、`temperature` はAIを賢くする設定ではないということです。

`temperature` を低くしたからといって、回答の正確性が保証されるわけではありません。

逆に、`temperature` を高くすると表現の幅は広がりやすいですが、間違いやズレも増えやすくなります。

今日の最初の理解は、こんな感じでした。

```text
temperatureとは、LLMの出力のランダムさを調整する設定。
temperatureを低くすると、回答は無難で安定した回答になりやすい。
temperatureを高くすると、回答はランダムで冒険的な回答になりやすいが、間違いやズレも増えやすい。
```

### Ollamaでtemperatureを変えてみました

次に、自分でOllamaの対話画面から `temperature` を変更してみました。

使ったモデルは、Day1から触っているTinySwallowです。

```text
hf.co/SakanaAI/TinySwallow-1.5B-Instruct-GGUF:Q5_K_M
```

Ollamaでは、対話画面で以下のように入力すると、パラメータを変えられます。

```text
/set parameter temperature 0.1
```

```text
/set parameter temperature 1.2
```

今日は、低めの `0.1` と高めの `1.2` を比べました。

### 事実説明で比べてみました

まずは、事実説明で試しました。

質問はこちらです。

```text
ローカルLLMとは何ですか。非エンジニアにも分かるように3行で説明してください。
```

`temperature 0.1` の回答はこうでした。

```text
ローカルLLMは、自分のパソコンやスマホの中に存在するAIのことで、インターネットを使わずに自分自身で動いて質問に答えたり文章を作成したりすることができます。
まるで家の中にある知能のようなものです！ 😊
ただし、クラウド型(LLM)と比べて処理速度が速く正確なのが特徴です。
```

文章としてはかなり自然です。

ただし、最後の「クラウド型と比べて処理速度が速く正確」という説明は言い切りすぎです。

ローカルLLMは手元のPCで動くので、ネットワーク遅延が少ないことはあります。

ただ、モデルサイズやPC性能によってはクラウド型より遅いこともありますし、正確さもクラウド型より高いとは限りません。

次に、`temperature 1.2` で同じ質問をしました。

```text
ローカルLLMは、インターネットなしに自宅のパソコンやスマホの中で動くAIみたいなもので、質問を理解して答えてくれます。
まるで自分のコンピュータの中にある賢い知能みたいですね！
バッテリーも使えるし、大容量なので処理が速くて正確です。
```

さらに怪しくなりました。

特に、

```text
バッテリーも使えるし、大容量なので処理が速くて正確です。
```

のあたりは、かなり雑です。

ここで分かったのは、`temperature` を低くしても正確性は保証されないし、高くすると事実説明ではさらに怪しくなることがある、ということです。

Day1でも感じましたが、LLMの回答は自然さと正確さを分けて見る必要があります。

### アイデア出しで比べてみました

次に、アイデア出しで試しました。

質問はこちらです。

```text
社内でローカルLLMを活用するアイデアを5つ出してください。
```

`temperature 0.1` では、以下のような回答が返ってきました。

```text
1. チャットボット
2. 翻訳ツール
3. 文章作成支援
4. 顧客対応自動化
5. 社内情報検索システム
```

かなり無難です。

どれも普通にあり得ますが、「よくあるAI活用案」という印象でした。

一方で、`temperature 1.2` ではこうなりました。

```text
1. 質問応答システム
2. 翻訳ツール
3. コード生成
4. 文書要約ツール
5. 顧客対応チャットボット
```

さっきよりは少し攻めている感じがありました。

`コード生成` や `文書要約ツール` が入ってきて、アイデアの幅は少し広がっています。

ただし、「電子メールの一部自動転送」や「自席にいるローカルLLM」のような、やや不自然な表現も出ていました。

ここでの学びは、アイデア出しでは `temperature` 高めが役立つこともある、ということです。

ただし、出てきたものをそのまま使うのではなく、人間が選別する必要があります。

### 文章生成でも比べてみました

最後に、文章生成でも試しました。

依頼はこちらです。

```text
ローカルLLMを学ぶ楽しさについて、note記事の冒頭文を150字程度で書いてください。
```

`temperature 0.1` の回答はこうでした。

```text
ローカルLLMは、まるで魔法使いのように、あなたのパソコンやスマホの中にAIが住んでくれる世界です！
インターネットに頼らず、自分の力だけで質問に答えたり文章を作ったりできるなんて、想像以上に楽しいですよ！
これから一緒に学び、その可能性を広げていきましょう。 🌐🧠✨
```

低temperatureでも、けっこうテンションが高いです。

これは `temperature` というより、モデル側の文体のクセが出ているのだと思います。

つまり、`temperature` は文体をゼロから変える設定ではありません。

モデルの元々のクセや、プロンプトの指示も大きく影響します。

次に `temperature 1.2` で試しました。

```text
ローカルLLMは、インターネットなしに自宅の大切なコンピュータの中で賢く生きるAIたちです。
一緒にその中に入ってみませんか？
指示を出すだけで「知恵」を絞って答えてくれますよ！

未知なる冒険が待っています！✨💻🧠
```

表現の幅は広がっています。

ただ、ちょっと不自然さも強くなりました。

特に、

```text
一緒にその中に入ってみませんか？
```

は、note記事の冒頭文としては少し怖いというか、意味がズレています。

高temperatureは、文章生成でも比喩やテンションが変な方向に行くことがあるようです。

### top_pについても軽く確認しました

最後に `top_p` についても確認しました。

今日は実際に `top_p` を変えて試すところまではやっていません。

ただ、ざっくりした理解としてはこうです。

```text
temperature = 候補の選び方の大胆さ
top_p = 候補に入れる範囲の広さ
```

自分の理解では、`top_p` が高いほど、そもそもの回答候補の幅が広がります。

そして `temperature` が高いほど、その候補の中からランダムで冒険的な選び方をしやすくなります。

たとえば、壁打ちで自由にアイデア出しをしてほしいときは、

- `top_p` を高めて、候補の幅を広げる
- `temperature` を高めて、その候補の中から少し意外なものも選びやすくする

という2つの要素があるのだと理解しました。

ただし、両方を高くすると、発想が広がる一方で、雑さやズレも増えそうです。

## 今日のハマりポイント

今日は大きなハマりはありませんでした。

ただ、`temperature` を低くしても回答が正確になるわけではない、という点は大事な発見でした。

なんとなく、`temperature` を低くすると「ちゃんとした回答」になるような気がしていました。

でも実際には、低temperatureでも「ローカルLLMはクラウド型より速く正確」と言い切っていました。

つまり、`temperature` は正確性のスイッチではありません。

あくまで、出力のブレ方を調整する設定です。

また、文章生成では低temperatureでもかなりキラキラした文章が出ました。

ここから、生成パラメータだけではなく、モデル自体のクセやプロンプトの書き方もかなり重要なのだと感じました。

## 今日の感想

Day3は、LLMの出力がどう揺れるのかを触る日でした。

`temperature` という言葉はなんとなく見知っていましたが、実際に同じ質問で比べるとかなり分かりやすかったです。

事実説明では、高temperatureは危なそうです。

一方で、アイデア出しでは少し幅が出るので、用途によっては役に立ちそうです。

ただ、どの場合でも人間の確認は必要です。

今日の結論はこれです。

- `temperature` は出力のランダムさを調整する
- 低くすると無難になりやすいが、正確性が保証されるわけではない
- 高くすると表現の幅は広がるが、間違いやズレも増えやすい
- `top_p` は次に出すトークン候補の範囲を調整する

生成パラメータは、AIを賢くする魔法の設定ではなく、出力のブレ方を調整するつまみなのだと思いました。

次は量子化について学ぶ予定です。

TinySwallowのモデル名に入っている `Q5_K_M` が何なのか、ようやく少し分かる日になりそうです。
