# Day14 PythonからローカルLLMを使う流れ

## 全体像

Pythonアプリは、APIクライアントを使って、自分のPCで動いているOllamaへリクエストを送る。Ollamaは指定されたローカルLLMを実行し、その回答をPythonアプリへ返す。

```text
ユーザー
  ↓ 入力
Pythonアプリ
  ↓ openaiライブラリがHTTPリクエストを送る
Ollamaの受付窓口（localhost:11434/v1）
  ↓ モデルを実行
TinySwallow
  ↓ 回答
Ollama
  ↓ APIレスポンス
Pythonアプリ
  ↓ 出力を検証
ユーザーへ表示
```

## `from openai import OpenAI`は何を読み込んでいるのか

```python
from openai import OpenAI
```

この`OpenAI`は、APIそのものでもLLMでもない。OpenAI公式のPythonライブラリに含まれる、APIへリクエストを送るためのクライアントである。

クライアントとは、接続先へ送るHTTPリクエストを組み立て、返ってきたレスポンスをPythonから扱いやすくする道具のこと。OpenAIのモデルを読み込んでいるわけではない。

## 接続先はどこで決まるのか

```python
client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",
)
```

`OpenAI`クライアントは通常OpenAIのサービスへ接続するために使われるが、`base_url`で別の接続先を指定できる。今回は`localhost:11434`を指定しているため、接続先はOpenAIではなく、自分のPCで起動しているOllamaになる。

## OpenAI互換APIとは

APIは、プログラム同士が決められた方法で情報を受け渡すための窓口である。APIには、接続先のURL、送る項目、返ってくるデータの形などの決まりがある。

OpenAIは、`model`や`messages`を送って回答を受け取るAPI形式を提供している。Ollamaも、その呼び出し方の一部を同じように受け付けられる。

このように、OpenAIのAPIと似た決まりで呼び出せることを「OpenAI互換」と呼ぶ。OpenAIのモデルやサーバーを使うという意味ではない。今回はOpenAI公式のPythonクライアントを道具として使い、OpenAI形式のリクエストをローカルのOllamaへ送っている。

Ollamaは受け取ったリクエストをTinySwallowが処理できる入力へ変換し、モデルを実行する。「互換」はすべての機能が完全に同一という意味ではなく、Ollamaが対応している範囲で利用できる。

## 各部品の役割

### Pythonアプリ

- ユーザーから入力を受け取る
- `messages`を組み立てる
- OllamaのAPIへリクエストを送る
- 返ってきた回答を表示・検証する
- 必要に応じて会話履歴を保持する

### Ollama

- ローカルLLMを管理する
- `localhost:11434`でAPIリクエストを受け付ける
- リクエストをモデル用の入力へ変換する
- 指定されたモデルを実行し、結果をAPIレスポンスとして返す

### TinySwallow

- Ollamaから渡された入力をもとに文章を生成する
- 指示へ必ず正確に従うとは限らない
- 会話履歴はモデル自身が保存するのではなく、Pythonアプリから毎回渡される

### openai Pythonライブラリ

- APIへリクエストを送るためのクライアントを提供する
- OpenAIのモデルそのものではない
- OpenAI形式のリクエストを作成し、指定された接続先へ送信する
- 今回は`base_url`を変更しているため、OpenAIのサーバーではなくローカルのOllamaへ接続する

## Week 2で作ったスクリプト

### `check_ollama_api.py`

Ollamaへ接続し、利用できるモデル一覧を取得する。PythonとOllamaが通信できるかを確認する最小構成。

### `ask_tinyswallow.py`

標準入力で質問を受け取り、TinySwallowへ送信して、完成した回答を一括表示する。

### `chat_cli.py`

`messages`にuserとassistantの発言を追加し、過去の会話を毎回モデルへ渡す。モデル自身が会話を記憶するのではなく、Pythonアプリが履歴を管理する。

### `stream_chat.py`

`stream=True`を指定し、生成された回答を断片ごとに表示する。接続エラー、APIエラー、ユーザーによる中断も処理する。

### `json_classifier.py`

分類結果をJSON形式で受け取り、`json.loads()`でPythonのデータへ変換する。JSONの構文、必要な項目、値の許可範囲を確認する。

### `text_tool.py`

要約・文章改善・分類の3モードを持つCLI。共通のAPI呼び出しを使い、モードに応じてプロンプトを切り替える。文章改善では生成結果を検証し、問題があれば原文へ戻す。

## LLMの出力を安全に扱うための確認

LLMへ形式を指示するだけでは、正しい出力になる保証はない。Python側でも段階的に確認する。

1. JSONなど、要求した形式として解析できるか
2. 必要な項目がすべて存在するか
3. 分類結果などの値が許可範囲内か
4. 入力にない情報の追加や、必要な情報の削除がないか
5. 意味が変わっていないか

問題のある出力をそのまま採用せず、エラー表示、再生成、原文へのフォールバックなどを選ぶ。

## Week 2を通して理解したこと

Pythonアプリ、Ollama、ローカルLLMは、それぞれ別の役割を持つ。Pythonアプリが入力や履歴を管理し、OllamaがAPIの窓口とモデル実行を担当し、TinySwallowが文章を生成する。

モデルの回答だけに処理を任せず、入力検証、例外処理、出力検証、フォールバックをPython側へ組み込むことが、アプリとして利用するうえで重要である。

## まだ曖昧なこと

- OpenAI互換APIで、Ollamaが対応している機能の範囲
- 会話履歴が長くなった場合の具体的な管理方法
- LLMによる検証の誤検出を減らす方法
- 不合格になった回答を再生成する方法
