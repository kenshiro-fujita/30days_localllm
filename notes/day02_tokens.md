# Day 2: トークンの仕組み

## 今日のテーマ

LLMが文章を「文字」ではなく「トークン」という単位で扱っていることを理解する。

## トークンとは

トークンとは、LLMが文章を処理するための単位。

人間は文章をそのまま文字や単語として読むが、LLMは文章をTokenizerで細かい部品に分解し、その部品を数値として扱う。

重要なのは、文字数とトークン数は必ずしも一致しないこと。

```text
トークン = LLMが文章を処理するための部品
Tokenizer = 文章をトークンに分割する仕組み
```

## 実際に試した結果

Hugging Face Tokenizer Playgroundで `Qwen/Qwen2.5-1.5B-Instruct` のTokenizerを使い、日本語と英語の分割を確認した。

TinySwallowそのものではないが、TinySwallowはQwen系の流れに近いため、今日はQwenのTokenizerで観察した。

### 短い質問の比較

```text
ローカルLLMとは何ですか？
```

```text
Characters: 14
Tokens: 12
分割: ロ / ー / カ / ル / LL / M / と / は / 何 / です / か / ？
```

```text
What is a local LLM?
```

```text
Characters: 20
Tokens: 7
分割: What / is / a / local / L / LM / ?
```

英語の方が文字数は多いが、トークン数は少なかった。

また、`LLM` はそのまま1トークンにはならず、日本語側では `LL / M`、英語側では `L / LM` に分かれていた。

ここから、比較的新しい単語、専門用語、固有名詞は分割されやすい可能性があると分かった。ただし、実際の分割はTokenizerの語彙に依存する。

### 日常文の比較

```text
今日は天気がいいですね。
```

```text
Characters: 12
Tokens: 12
分割: 今 / 日 / は / 天 / 気 / が / い / い / です / � / � / 。
```

```text
The weather is nice today.
```

```text
Characters: 26
Tokens: 6
分割: The / weather / is / nice / today / .
```

日本語では、人間には「今日」「天気」「いい」などのまとまりに見えるが、Tokenizer上ではかなり細かく分かれていた。

また、「ね」が `� / �` のように表示された。これはTokenizer Playground上の表示の問題、または内部のバイト単位表現が見えている可能性がある。

ここで重要なのは、Tokenizerは人間が自然に感じる分け方とは限らないということ。

## 業務文の比較


```text

Tokens: 49
```

表示上は、以下のように読めない断片が多く出た。

```text
会��では、来月のAI活用���修に向けて、参加者アン��ートの��計と事前����の内容を����しました。
```

```text
In the meeting, we reviewed the participant survey design and pre-work content for next month's AI training.
```

```text
Characters: 108
Tokens: 21
```

人間の目では英語の方が長いが、LLM内部では日本語の方が倍以上重い入力になっていた。

日本語の業務文には、以下のような複合語が含まれていた。

- AI活用研修
- 参加者アンケート
- 事前課題

人間には自然なまとまりに見えるが、Tokenizer上では細かく分解され、トークン数が増えやすい。

## 日本語LLMでトークン効率が重要な理由

日本語は、同じ意味の文章でも英語よりトークン数が多くなる場合がある。

トークン効率が悪いと、同じコンテキスト長でも渡せる情報量が減る。

その結果、以下に影響する。

- 処理速度
- メモリ使用量
- APIコスト
- RAGで渡せる資料量
- 長文資料を扱うときの精度

特にRAGでは、検索で見つけた資料をプロンプトに入れてLLMへ渡す。

日本語文書でトークン数が増えやすい場合、同じコンテキスト長でも渡せる資料量が減る。

```text
トークン効率が悪い = 同じコンテキスト長でも詰め込める情報が少ない
```

## コンテキスト長とは

コンテキスト長とは、LLMが一度に扱えるトークン数の上限。

これは入力できる文字数の上限ではなく、入力文、システム指示、会話履歴、資料、出力予定分を含めたトークン数の上限。

```text
コンテキスト長 = 入力・出力を含めてLLMが一度に扱えるトークン数の上限
```

日本語でトークン数が増えやすい場合、同じコンテキスト長でも入れられる文章量が少なくなる。

## 今日のまとめ

```text
LLMは文章をトークンという単位に分けて処理する。

トークン分割は、人間が自然に感じる分け方とは限らない。

日本語は英語より、同じ意味でもトークンが多くなることがある。

トークン数が多い文章は、LLMにとって重い入力になる。
```
