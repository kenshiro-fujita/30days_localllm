# Day27 学習メモ：本番ファインチューニングと評価

## 今日のテーマ

Day26で疎通確認したQLoRA設定を使って本番学習を行い、base Qwenとtuned Qwenを固定評価で比較する。

## 今日理解したこと

- batch size 1でtrain 80件を240 iteration学習すると、約3周に相当する。
- 今回も7Bモデル全体ではなく、約288万のLoRAパラメータ（全体の0.038%）だけを学習した。
- Train lossは学習データ、Val lossは学習に使わないvalidデータにおける次トークン予測のズレを表す。
- Train lossは0.985から0.269へ下がり、Val lossも1.257から0.7前後まで下がった。学習データと似た文章の予測は改善したと読める。
- lossは、3区分の形式遵守、矛盾検出、情報の捏造、人間にとっての読みやすさを直接採点する数値ではない。
- lossが下がっても、実際の回答品質が必ず改善するわけではない。固定評価問題による実技評価が別に必要である。
- tunedモデルは入力情報を素直に保持し、baseモデルより捏造が減ったケースがあった。
- 一方、狙って学習させた「要点・決定事項・次の行動」の形式を守れないケースが増えた。
- 矛盾する2つの情報を保持できても、その矛盾を指摘して「判断できない」と結論づけられるとは限らない。
- 特定タスクへのFTは、無関係な質問にも回答の短さや「担当者未定」のような表現の癖を持ち込む可能性がある。
- 学習で指定した回答方法や知識によって、意図しない偏りが出る場合がある。

## 今日出てきた重要用語

- loss：モデルの次トークン予測が教師データの正解からどれだけずれているかを表す数値
- Train loss：学習に使ったデータに対するloss
- Val loss：学習に使わない検証データに対するloss
- 過学習：学習データには強くなる一方、未知のデータで性能が上がらない、または悪化する状態
- 副作用：特定タスクへ寄せた学習が、汎用回答の形式や内容にも意図せず影響すること

## 実行したコマンドと、その意味

```text
mlx_lm.lora --model models/RLT-7B-4bit --train --data dataset ... --iters 240 ...
```

80件のtrainデータを約3周する本番QLoRA学習を行い、80、160、240 iteration時点と最終版のadapterを保存した。

```text
python src/run_ft_eval.py --model models/RLT-7B-4bit ...
```

固定したFT評価10件をbaseモデルへ渡し、user入力、reference、実出力を保存した。

```text
python src/run_ft_eval.py --model models/RLT-7B-4bit --adapter-path finetune/tuned_adapter_v1 ...
```

同じ10件をtunedモデルへ渡し、adapterの有無だけが異なる条件で比較できる出力を保存した。

```text
python src/run_general_eval.py --model models/RLT-7B-4bit ...
```

固定した汎用質問と素材を使い、baseモデルとtunedモデルの一般説明、素材読解、矛盾検出などを比較した。

## 自分の言葉でのまとめ

今回のFTは、良くなった部分も悪くなった部分もあるとしか言いようがない。素直に情報を保持したり、捏造がなくなったりした点は良かったが、学習させたはずの形式を守れないケースがむしろ増えたのは引いた。lossが下がったことと、実際に使える回答になったことは別だった。また、学習で指定した回答方法や知識によって、汎用回答にも意図しない偏りが出る場合がある。
