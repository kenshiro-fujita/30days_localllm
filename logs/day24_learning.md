# Day24 学習メモ：シンセティックデータ生成①

## 今日のテーマ

設計済みのプロンプトを使ってmessages形式JSONLのシンセティックデータを生成し、形式と内容の品質を確認して評価用データを分離する。

## 今日理解したこと

- シンセティックデータは、LLMに生成させた人工的な学習データ。今回はGeminiとClaudeへ同じ指示を渡し、出力の形式と内容を比較した。
- JSONLは、見た目がJSONらしいだけでは不十分で、1物理行につき1件のJSONオブジェクトとして読み込める必要がある。
- `jq`を使うと、件数、最上位キー、messagesの数、roleの順序、system文の統一、user入力の重複を機械的に確認できる。
- 構文が正しいことと、教師データとして内容が正しいことは別。元メモとassistantの要約を照合する目視確認も必要になる。
- 担当者や期限がない場合でも、元メモに実施予定の作業があれば「次の行動はありません」としてはいけない。今回の設計では「担当者未定」として行動を残す。
- 評価用データは学習前に分離しておき、Day25でtrain側へ混ざらないようにする。
- 生成件数を満たすだけでなく、低品質な1件を除外し、検査済みの別候補で補うことで30件を維持した。

## 今日出てきた重要用語

- シンセティックデータ：LLMなどを使って人工的に作成した学習用データ
- JSONL：1行に1件のJSONオブジェクトを記録する形式
- 教師データ：入力と、モデルに出してほしい理想的な出力を組にした学習例
- 評価用データ：学習には使わず、学習後のモデルの振る舞いを確認するために残すデータ
- データリーク：評価に使うデータが学習データへ混ざり、正しい性能評価ができなくなること
- 構文検証：ファイルがJSONLとして機械的に読み込めるか確認すること
- 内容検証：元の入力に対して正解例の内容が適切か確認すること

## 実行したコマンドと、その意味

```text
cat dataset/generate_prompt.md
```

Day23で作成した生成プロンプトを確認した。

```text
cp Geminiの出力ファイル dataset/raw_generated_v0.jsonl
```

最初の10件を候補データの初版として保存した。

```text
awk 'BEGIN { print "" } { print }' 追加ファイル >> dataset/raw_generated_v0.jsonl
```

既存ファイルの末尾に改行がない状態でもJSON同士が連結しないよう、先頭に改行を補って10件を追記した。

```text
cat 追加ファイル >> dataset/raw_generated_v0.jsonl
```

末尾改行があることを確認したうえで、別分野の10件を候補ファイルへ追記した。

```text
jq -c -s '[.[0], .[9], .[10], .[19], .[29]][]' dataset/raw_generated_v0.jsonl > dataset/eval_seed.jsonl
```

30件から5件を選び、評価用シードとして別ファイルへ保存した。

```text
jq -c -s 'del(.[17])[]' dataset/raw_generated_v0.jsonl > dataset/raw_generated_v0.tmp.jsonl && mv dataset/raw_generated_v0.tmp.jsonl dataset/raw_generated_v0.jsonl
```

内容確認で問題が見つかった18件目を候補データから除外した。

```text
sed -n '1p' Claudeの出力ファイル >> dataset/raw_generated_v0.jsonl
```

検査済みのClaude出力から良質な1件を追加し、候補を30件へ戻した。

## 今日作成したもの

- `dataset/raw_generated_v0.jsonl`：品質確認後の学習候補30件
- `dataset/eval_seed.jsonl`：Day25で評価データへ統合する5件

GeminiとClaudeでの生成、ファイルへの保存・追記、評価用5件の抽出、低品質例の削除はユーザーが実行した。CodexはJSONLの機械検証、30件の内容確認、除外対象の特定、最終検証を行った。

## 自分の言葉でのまとめ

JSONLとして読み込めることと、正解の内容が正しいことは別です。`jq`で形式や重複を確認したあと、元メモにない情報を足していないか、逆に必要な行動を落としていないかも確認する必要があります。評価用の5件は先に分けて、学習データへ混ざらないようにします。
