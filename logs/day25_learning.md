# Day25 学習メモ：シンセティックデータ生成②

## 今日のテーマ

シンセティックデータを100件まで増やし、train・valid・evalへ分割して、JSONLの構造とデータリークを検証する。

## 今日理解したこと

- JSONLの件数確認では、`wc -l`だけでなくJSONとして読み込んだ件数も確認する。末尾改行がないと、`wc -l`は実際のデータ件数より1件少なく表示される。
- LLMが生成したJSONLは、構文やroleの順序が正しくても、元メモに書かれた予定や次の行動が要約から落ちることがある。
- trainはモデルの学習、validは学習中の調整や確認、evalは学習後の最終評価に使う。
- 同じuser入力がtrainとevalの両方に入ると、未知の入力へ対応できたのか、学習中に見た入力を再現したのか判断しにくくなる。これが評価データのリークである。
- 評価用データは学習前に分離し、userのcontentが完全一致していないか機械的に検査する。
- `eval/ft_questions.md`にはタスク名だけでなく、実際にモデルへ渡すuser入力と比較対象のreference出力を固定する。
- 検証処理をスクリプトにすると、Day26以降も同じ条件でデータセットを再確認できる。

## 今日出てきた重要用語

- train：モデルの重みを更新するための学習データ
- valid：学習中の状態や設定を確認するための検証データ
- eval：学習後のモデルを最終評価するためのデータ
- reference出力：モデル出力を評価するときに比較する理想的な回答
- データリーク：評価用の入力や正解が学習データへ混ざり、モデルが評価前に問題を見た状態になること。その結果、未知の入力への実力より評価が良く見える可能性がある
- 完全一致チェック：userのcontentが文字列として同一かを比較する検査

## 実行したコマンドと、その意味

```text
jq -c . 対象ファイル | wc -l
```

各行をJSONとして読み込み、正常にパースできたデータ件数を確認した。

```text
jq -r '.messages[0].content' 対象ファイル | sort | uniq -c
```

全データのsystem文が同じ内容に統一されているか確認した。

```text
cat 追加ファイル >> dataset/raw_generated_v0.jsonl
```

内容確認済みの追加データを候補データへ追記した。

```text
jq -c -s '.[52, 63, 76, 88, 99]' dataset/raw_generated_v0.jsonl >> dataset/eval.jsonl
```

新しい5分野から形式の異なる5件を選び、Day24の評価用シード5件と合わせて評価用10件にした。配列の添字は0から始まる。

```text
python src/validate_jsonl.py dataset/train.jsonl dataset/valid.jsonl dataset/eval.jsonl
```

3ファイルのJSONL構造、role順序、user・assistantの空欄、分割間のuser入力重複を一括で検証した。

## 今日作成したもの

- `dataset/raw_generated_v0.jsonl`：内容確認済みの候補データ100件
- `dataset/train.jsonl`：学習用80件
- `dataset/valid.jsonl`：検証用10件
- `dataset/eval.jsonl`：最終評価用10件
- `src/validate_jsonl.py`：JSONL構造と分割間リークの検証スクリプト
- `eval/ft_questions.md`：Day27で使う固定評価問題10件

追加データの生成、ファイル保存、追記、分割、検証スクリプトの実行はユーザーが行った。Codexは50件の内容照合と訂正、分割方法とコードの提示、最終検証を行った。

## まだ曖昧なこと

- 完全一致ではないが意味がほぼ同じuser入力を、どの基準で類似データとして検出するか
- 80件のtrainデータで、Day26の小規模なファインチューニングにどの程度の変化が出るか
- validデータが実際の学習処理でどのように使われ、lossへどう表れるか

## 自分の言葉でのまとめ

100件を作るだけでは学習データは完成しません。内容を確認したうえで、train・valid・evalへ役割を分け、評価用の入力が学習側へ混ざっていないことを確認する必要があります。今回は検証スクリプトを作ったので、次回以降も同じ基準で確認できます。
