# Day 4 Learning Memo

## 今日のテーマ

量子化の基本を理解し、現在使っているTinySwallowの `Q5_K_M` が何を表しているか確認する。

## 今日理解したこと

### 量子化とは

量子化とは、LLLモデルの内部にある大量のパラメータの数値を、より少ないビット数で表現するために大まかな値に置き換えて、モデルを軽くする方法。

量子化してもパラメータの個数そのものは基本的に変わらない。変わるのは、各パラメータの数値を記録する細かさ。

```text
変わらないもの：パラメータの個数
変わるもの：各パラメータを記録するビット数と数値精度
```

量子化によって、ファイルサイズやメモリ使用量を減らせる。一方で、モデル内部の数値を大まかに表現するため、回答品質が低下する可能性がある。

処理が軽くなった結果、環境によっては読み込みや推論が速くなることもある。ただし、ビット数を減らせば必ず速くなるわけではなく、CPU・GPUや実行環境、量子化方式にも左右される。

### F16・Q8・Q5・Q4の関係

一般的には、次の順で数値を細かく表現でき、ファイルサイズも大きくなりやすい。

```text
←大きくなりやすい・数値が細かい
F16 → Q8 → Q5 → Q4
→小さくなりやすい・数値が粗い
```

- `F16`: 数値を16ビットの浮動小数点形式で表す
- `Q8`: 主に8ビット級で量子化する
- `Q5`: 主に5ビット級で量子化する
- `Q4`: 主に4ビット級で量子化する

実際の量子化方式では、すべての数値を単純に同じビット数で保存するとは限らない。そのため、ビット数から計算した容量は概算になる。

### GGUFと量子化方式は別のもの

`GGUF` は、ローカルLLMのモデル本体や、読み込みに必要な情報をまとめて保存・配布するためのファイル形式。

`Q5_K_M` は、GGUFファイル内にあるモデルの数値を軽量に表現するための量子化方式。

```text
GGUF = モデルを保存するファイル形式
Q5_K_M = モデル内部の数値を軽く表現する方式
```

GGUFだから必ず量子化されているわけでもなく、同じGGUF形式でもF16、Q8、Q5、Q4など異なる精度のデータを保存できる。

### TinySwallowで実際に確認したこと

現在Ollamaで使っているモデル:

```text
hf.co/SakanaAI/TinySwallow-1.5B-Instruct-GGUF:Q5_K_M
```

`ollama show` では、次の情報を確認した。

```text
architecture        qwen2
parameters          1.54B
context length      32768
embedding length    1536
quantization        Q5_K_M
```

パラメータ数は約15億4千万で、量子化方式は `Q5_K_M`。

TinySwallowの公式GGUF配布ページでは、次の2ファイルを確認した。

| 量子化方式 | ファイルサイズ |
|---|---:|
| Q5_K_M | 1.13 GB |
| Q8_0 | 1.65 GB |

`Q5_K_M` は `Q8_0` より約0.52 GB小さい。Q8よりモデルを軽くしつつ、軽さと回答品質のバランスを取りやすい方式と理解した。

ただし、TinySwallowのQ5版とQ8版を実際に同じ質問で比較したわけではない。そのため、回答品質や速度にどの程度の差があるかはまだ確認できていない。

公式GGUF配布ページではF16版を確認していない。学習中に出てきたF16の容量は、Codexが量子化前との違いを説明するために出した仮定の計算であり、TinySwallowの実際のF16版を確認した結果ではない。

## 今日出てきた重要用語

### パラメータ

LLMが学習によって獲得した大量の数値。主に重みを指す。量子化しても、その個数は基本的に変わらない。

### ビット

コンピュータが情報を表現する最小単位。数値の記録に使うビット数が多いほど細かく表現しやすいが、必要なデータ量も増える。

### 量子化

モデル内部の数値を、少ないビット数で表せる大まかな値に置き換え、モデルを軽くする方法。

### GGUF

モデル本体と、読み込みに必要なメタデータなどをまとめて保存・配布するためのファイル形式。

### Q5_K_M

主に5ビット級の表現を使うK-quant系の量子化方式。`M` はMediumを表し、軽さと品質のバランスを取る構成と理解した。

### Q8_0

主に8ビット級で数値を表現する量子化方式。今回確認したTinySwallowでは、Q5_K_M版よりファイルサイズが大きかった。

### Embedding length

トークンをモデル内部で表す数字の並びの長さ。TinySwallowでは1536と表示された。Embedding自体はDay 15で詳しく学ぶ予定。
