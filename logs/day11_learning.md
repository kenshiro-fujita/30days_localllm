# Day 11 学習メモ

## 今日のテーマ

OpenAI互換APIのストリーミング応答を使い、TinySwallowの回答を生成された断片から逐次表示する。

## 今日理解したこと

### 一括表示とストリーミング表示の違い

一括表示では、LLMが回答を最後まで生成してから、完成した回答全体を表示する。

ストリーミング表示では、回答の断片が生成されて届き次第、画面へ表示する。総生成時間が必ず短くなるわけではないが、処理が進んでいることが見えるため、待ち時間が短く感じられる。

### `stream=True` と `chunk`

`client.chat.completions.create()` に `stream=True` を指定すると、完成済みの回答ではなく、回答の断片が順番に返る。

```python
stream = client.chat.completions.create(
    model="hf.co/SakanaAI/TinySwallow-1.5B-Instruct-GGUF:Q5_K_M",
    messages=messages,
    stream=True,
)
```

返ってくる各断片を `for chunk in stream` で一つずつ受け取る。新しく届いた文章は `chunk.choices[0].delta.content` から取得する。

確認用に各断片を表示したところ、`「ロ」`、`「ーカ」`、`「ル」` のように、実際に細かく分かれて届いていることを確認できた。

### 逐次表示に必要な `print()` の設定

```python
print(content, end="", flush=True)
```

- `end=""`: 断片ごとに改行せず、文章をつなげて表示する
- `flush=True`: 表示を内部にためず、すぐターミナルへ出す

### ストリーミングは回答品質を改善する機能ではない

TinySwallowにローカルLLMについて質問したところ、「ロケーション・オンリーのLarge Language Model」の略だという誤った説明が生成された。

ストリーミングは回答の表示方法を変える機能であり、モデルの正確さやハルシネーションを改善するものではない。

### 例外処理

`try` / `except` を使い、次の問題へ対応した。

- `APIConnectionError`: Ollamaへ接続できない場合
- `APIError`: APIの処理中にエラーが起きた場合
- `KeyboardInterrupt`: ユーザーが `Ctrl+C` で処理を中断した場合

長い回答の生成中に `Ctrl+C` を押し、「処理を中断しました。」と表示されることを確認した。

## 今日出てきた重要用語

- ストリーミング: すべての処理の完了を待たず、届いたデータから順次扱う方式
- `stream=True`: OpenAI互換APIでストリーミング応答を有効にする指定
- `chunk`: ストリーミングで届く回答の小さな断片
- `delta.content`: 各断片に新しく含まれる文章
- `flush=True`: 出力をためず、すぐ画面へ表示する指定
- 例外処理: エラーや中断が起きた場合の動作をあらかじめ決める処理
- `KeyboardInterrupt`: `Ctrl+C` による中断を表す例外

## 自分の言葉でのまとめ
