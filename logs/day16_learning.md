# Day 16 学習メモ

## 今日のテーマ

`bge-m3`とコサイン類似度を使い、入力文に近い文章をスコア付きで検索する。

## 今日理解したこと

### `bge-m3`は文章を1024次元のベクトルにする

Ollamaの`/api/embed`へ「猫がソファで眠っています」を送ると、大量の小数を含むJSONが返った。`jq`で配列の長さを調べ、今回の`bge-m3`では1文章が1024個の数値で表現されることを確認した。

### 複数の文章をまとめてEmbeddingできる

10文章をリストとして`/api/embed`へ渡すと、文章ごとに1つ、合計10個のベクトルが返る。それぞれのベクトルは1024次元だった。

### コサイン類似度はベクトルの向きの近さを測る

2つのベクトルの内積を、それぞれのベクトルの大きさで割ってコサイン類似度を求める。今回のプログラムでは、質問文のベクトルと10文章のベクトルを1件ずつ比較し、スコアの高い順に並べた。

### ベクトル検索は条件を厳密に判定するものではない

「今日は忙しいので短時間で作れる料理を知りたい」では、「忙しい日は短時間で作れる料理が便利です」が`0.8411`で1位になった。一方、「休日に時間をかけてカレーを煮込みます」も2位だった。

料理と時間に関する文脈は近いが、「忙しい」と「休日」、「短時間」と「時間をかける」は反対である。Embedding検索は文章全体の意味の近さを順位付けするもので、個々の条件を必ず満たす保証はない。

### 類似度スコアは相対的に見る

特定の数値以上なら常に正解、という共通の基準があるわけではない。モデルや検索対象によって値が変わるため、同じ検索内での順位やスコア差を観察する。

### docstringとコメントの役割

- `"""..."""`を関数の先頭に置くと、その関数全体の目的を説明するdocstringになる
- `#`コメントは、関数内の処理の目的や流れを説明する
- docstringは`関数名.__doc__`からPythonで取得できる

## 今日出てきた重要用語

- Embedding: 文章の意味や特徴をベクトルで表現すること
- 次元: ベクトルを構成する数値の個数。今回の`bge-m3`は1024次元
- コサイン類似度: ベクトル同士の向きの近さを測る指標
- 内積: 同じ位置の数値同士を掛け、その合計を求めたもの
- docstring: 関数やクラスなどの目的を説明する文字列
- 標準入力: `input()`を使い、プログラムの実行中にユーザーから文字列を受け取る仕組み

## 実行したコマンドと、その意味

```bash
curl http://localhost:11434/api/embed \
  -d '{
    "model": "bge-m3",
    "input": "猫がソファで眠っています"
  }'
```

OllamaのEmbedding APIへ1文章を送り、ベクトルを含むJSONを取得した。

```bash
curl -s http://localhost:11434/api/embed \
  -d '{
    "model": "bge-m3",
    "input": "猫がソファで眠っています"
  }' \
  | jq '.embeddings[0] | length'
```

Embedding結果の最初のベクトルに含まれる数値を数え、1024次元であることを確認した。

## 自分の言葉でのまとめ

文章を`bge-m3`で1024次元のベクトルにし、質問文とのコサイン類似度を計算すると、意味が近い文章をスコア順に検索できます。ただし、文章全体の話題が近ければ反対条件を含む文章も上位になり得るため、スコアは正解判定ではなく候補の順位として見る必要があります。
