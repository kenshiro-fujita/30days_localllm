# Day 5 Learning Memo

## 今日のテーマ

固定した10問の評価セットを使い、TinySwallowとQwen2.5-1.5B-Instructの回答を比較する。

## 今日理解したこと

### 同じ質問で比較する意味

モデルの違いを見るときは、質問・参照資料・評価観点を固定する必要がある。

今回は `eval/questions.md` のQ1〜Q10と、`eval/materials.md` の架空資料を両モデルに使った。Q1〜Q5では説明力・指示追従・業務観点を、Q6〜Q10では資料に書かれた数値・条件・制約を保持できるかを見た。

### TinySwallowとQwenは得意な質問が違った

TinySwallowは、ローカルLLMの説明、短いFAQ回答、業務ヒアリングの質問出しでは、Qwenより比較的ましな回答を出した。一方で、RAGの正式名称と仕組みを誤り、長い資料の要約では背景と決定事項を混ぜたり、数値を取り違えたりした。

Qwenは、会議メモを決定事項・未決事項・次アクションに分ける要約と、FAQから数値・条件を抜き出す回答が正確だった。一方で、基本概念の説明、現場ヒアリング、仕様の矛盾検出、業務提案では大きく崩れる回答があった。

同じ1.5B級モデルでも、モデル名やサイズだけで「どちらが優秀か」は決められない。用途ごとに、実際の質問と資料を使って確認する必要がある。

### RAGで資料を渡しても確認は必要

資料を渡した質問でも、両モデルには次のような問題があった。

- 資料にない運用や数値を補う
- 指定された制約を落とす、または逆の提案をする
- もっとも重要な矛盾を見落とす

特にQ10では、会議メモの「自動送信せず担当者確認を必須にする」という方針があるにもかかわらず、両モデルとも自動返信などを提案した。RAGは資料に基づく回答を助ける仕組みだが、正しさを保証するものではない。

### 回答評価で見る観点

今回は次の観点で回答を見た。

- 正確さ: 用語、数値、条件が事実や資料と合っているか
- 指示追従: 指定された数、形式、対象範囲を守れているか
- 資料への忠実さ: 書かれていない内容を足していないか
- 制約の保持: 人間確認、承認フロー、対象範囲などを守れているか

文章が自然でも、この観点で確認すると実務でそのまま使えない回答があることが分かった。

## 今日出てきた重要用語

### 評価セット

モデル比較のために固定した質問と参照資料の組。質問を変えずに使うことで、回答差を比較しやすくする。

### 指示追従

「8個挙げる」「3区分に分ける」「資料AとCだけを使う」のような依頼条件を、モデルが守れるかという観点。

### ハルシネーション

資料にない数値・手順・運用を、もっともらしく補ってしまうこと。今回の手順抽出や業務改善提案で確認できた。

### RAG

`Retrieval-Augmented Generation` の略。関連する外部資料を検索し、その結果をLLMへの入力に加えて回答を生成する仕組み。資料を渡しても、回答内容の確認は必要。

## 実行したコマンドと、その意味

### Qwenが保存済みか確認

```bash
ollama list | grep -i qwen
```

OllamaにQwenのモデルが保存されているかを確認する。`rg` が入っていない環境では、標準コマンドの `grep` を使える。

### Qwenを取得

```bash
ollama pull qwen2.5:1.5b-instruct
```

Qwen2.5-1.5B-InstructをOllamaへダウンロードする。

### Pythonスクリプトの文法確認

```bash
python3 -m py_compile eval/run_day05_qwen.py
```

スクリプトを実行せず、Pythonとして読めるか確認する。`__pycache__` に `.pyc` ファイルが作られるが、Pythonのキャッシュなので問題ない。

### Qwenの10問を一括実行

```bash
python3 eval/run_day05_qwen.py
```

`eval/questions.md` と `eval/materials.md` を読み、Q1〜Q10をQwenへ順に送る。回答は `eval/runs/day05_qwen_base.md` に保存される。

## 自分の言葉でのまとめ

小型ローカルLLMは、質問によっては使えそうな回答をするが、文章が自然だからといって正しいわけではなかった。特に専門用語、資料の数値、承認フローのような制約は、人が元の資料と見比べて確認する必要がある。

TinySwallowとQwenは一長一短だった。今回のQwenは会議メモ要約とFAQで良かったが、基本説明や業務提案ではかなり厳しかった。用途に合わせた評価をしてから使うことが大切だと理解した。
