# Day 2 Learning Memo

## 今日のテーマ

トークンの仕組みを理解する。

## 今日理解したこと

### トークンとは

トークンとは、LLMが文章を処理するための単位。

LLMは文章をそのまま文字として読むのではなく、Tokenizerで細かい部品に分割してから扱う。

今日の理解:

```text
トークンとは、LLMが文章を処理するための単位。
文字数とトークン数は、必ずしも一致せず、言語や状況で異なる。
```

### Tokenizerとは

Tokenizerとは、文章をトークンに分割する仕組み。

LLM本体に文章を渡す前に、「この文章をどの部品に分けるか」を決める係。

### 日本語と英語でトークン数が違う

Hugging Face Tokenizer Playgroundで `Qwen/Qwen2.5-1.5B-Instruct` のTokenizerを使い、同じ意味の日本語と英語を比較した。

```text
ローカルLLMとは何ですか？
Characters: 14
Tokens: 12
分割: ロ / ー / カ / ル / LL / M / と / は / 何 / です / か / ？
```

```text
What is a local LLM?
Characters: 20
Tokens: 7
分割: What / is / a / local / L / LM / ?
```

英語の方が文字数は多いが、トークン数は少なかった。

`LLM` は比較的新しい・専門寄りの単語なので、1トークンではなく `LL / M` や `L / LM` のように分割されていた。

### Tokenizerの分け方は人間の感覚と違う

```text
今日は天気がいいですね。
Characters: 12
Tokens: 12
分割: 今 / 日 / は / 天 / 気 / が / い / い / です / � / � / 。
```

```text
The weather is nice today.
Characters: 26
Tokens: 6
分割: The / weather / is / nice / today / .
```

日本語では「今日」「天気」「いい」のような人間に自然なまとまりではなく、かなり細かく分割されていた。

また、「ね」が `� / �` のように表示された。

これはTokenizer Playground上の表示の問題、または内部のバイト単位表現が見えている可能性がある。

今日の理解:

```text
トークン分割は、人間が自然に感じる分け方とは限らない。
```

### 業務文では日本語のトークン数がかなり増える

```text
会議では、来月のAI活用研修に向けて、参加者アンケートの設計と事前課題の内容を確認しました。
Characters: 46
Tokens: 49
```

表示上は、以下のように読めない断片が多く出た。

```text
会��では、来月のAI活用���修に向けて、参加者アン��ートの��計と事前����の内容を����しました。
```

英語では以下だった。

```text
In the meeting, we reviewed the participant survey design and pre-work content for next month's AI training.
Characters: 108
Tokens: 21
```

人間の目では英語の方が長いが、LLM内部では日本語の方が倍以上重い入力になっていた。

### 日本語LLMでトークン効率が重要な理由

今日の理解:

```text
日本語はトークン効率が悪くなる場合が多い。
トークン効率が悪いとLLMの性能やコストが悪化して、適切な情報の取得・出力がしづらくなる。
```

もう少し整理すると、以下。

```text
日本語は、同じ意味の文章でも英語よりトークン数が多くなる場合がある。
トークン効率が悪いと、同じコンテキスト長でも渡せる情報量が減る。
その結果、処理速度・メモリ使用量・APIコスト・RAGで渡せる資料量などに影響する。
```

### コンテキスト長とは

コンテキスト長とは、LLMが一度に扱えるトークン数の上限。

入力文、システム指示、会話履歴、資料、出力予定分を含めて、その範囲に収める必要がある。

```text
コンテキスト長 = 入力できる文字数の上限ではなく、入力・出力を含めたトークン数の上限
```

## 今日出てきた重要用語

### トークン

LLMが文章を処理するための単位。

### Tokenizer

文章をトークンに分割する仕組み。

### トークン効率

同じ意味や同じ情報量を、どれくらい少ないトークン数で表せるか。

### コンテキスト長

LLMが一度に扱えるトークン数の上限。

### RAG

検索した資料をプロンプトに入れて、LLMに回答させる仕組み。
トークン効率が悪いと、RAGで渡せる資料量が減る。

## 自分の言葉でのまとめ

LLMは文章をトークンという単位に分けて処理する。

トークン分割は、人間が自然に感じる分け方とは限らない。

日本語は英語より、同じ意味でもトークンが多くなることがある。

トークン数が多い文章は、LLMにとって重い入力になる。
