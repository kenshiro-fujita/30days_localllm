# Day 1 Learning Memo

## 今日のテーマ

TinySwallowをローカルで動かし、ローカルLLMを使う感覚をつかむ。

## 今日理解したこと

### Ollamaとは

Ollamaは、ローカルPC上でLLMを動かすための実行環境。

もう少し噛み砕くと、Ollamaは以下をまとめて面倒見てくれる道具。

- LLMモデルをダウンロードする
- モデルをPC上で読み込む
- ターミナルから会話できるようにする
- API経由でPythonなどから呼べるようにする
- モデル一覧を管理する

今の理解では、以下のように捉えておけばよい。

```text
Ollama = ローカルPCでLLMをダウンロード・管理・実行するための道具
```

Dockerに少し近い感覚もある。

```text
Docker: アプリ実行環境をまとめて扱いやすくする道具
Ollama: LLMモデルをローカルで扱いやすくする道具
```

ただし、OllamaはDockerそのものではなく、LLMに特化した道具。

### `ollama --version` の意味

実行したコマンド:

```bash
ollama --version
```

結果:

```text
ollama version is 0.31.1
```

このコマンドで分かること:

- Ollamaがインストールされているか
- インストールされているOllamaのバージョン

今回の環境では、Ollama 0.31.1 が入っている。

### `ollama list` の意味

実行したコマンド:

```bash
ollama list
```

結果:

```text
NAME                                                    ID              SIZE      MODIFIED
hf.co/SakanaAI/TinySwallow-1.5B-Instruct-GGUF:Q5_K_M    54c14a1203d8    1.1 GB    9 hours ago
```

このコマンドで分かること:

- Ollamaに登録・保存されているモデル一覧
- モデル名
- モデルの内部ID
- モデルサイズ
- いつ追加・更新されたか

`ID` はOllamaが内部でモデルを識別するための値。
人間が覚える必要はない。
GitのコミットIDやDockerイメージIDに近い感覚。

`ollama list` は「今まさに動いているモデル」ではなく、「Ollamaに登録されているモデル」を見るコマンド。

### TinySwallowとは

TinySwallowは、日本語向けの小型LLMモデル。
今回のDay 1では、Ollama上でTinySwallowを動かしている。

モデル名:

```text
hf.co/SakanaAI/TinySwallow-1.5B-Instruct-GGUF:Q5_K_M
```

ざっくり分解すると以下。

- `hf.co`: Hugging Faceから取得したモデル
- `SakanaAI`: Sakana AIが公開している
- `TinySwallow-1.5B-Instruct`: TinySwallowという1.5B規模の指示応答モデル
- `GGUF`: ローカル推論向けのモデル形式
- `Q5_K_M`: 量子化の種類

今日の時点では、以下の理解でよい。

```text
TinySwallow = 今回Ollamaで動かしている日本語向け小型LLMモデル
```

### LLMに自分が誰かを聞いても正確とは限らない

TinySwallowに以下のように質問した。

```text
こんにちは！あなたはどのような存在ですか？
```

すると、TinySwallowとして実行しているにもかかわらず、以下のようにGemmaと名乗った。

```text
私はGemma、Google DeepMindによって訓練されたAIアシスタントです。
```

ここから分かったこと:

- LLMに「あなたは誰？」と聞いても、正確なモデル名が返ってくるとは限らない
- LLMは現在の実行環境やモデル名を正確に参照して答えているわけではない
- モデル名はLLM本人に聞くのではなく、`ollama list` など実行環境側で確認する

### LLMの回答は自然でも正しいとは限らない

TinySwallowに以下の正式評価質問Q1を投げた。

```text
ローカルLLMとは何ですか。クラウド型LLMとの違いを、非エンジニアにも分かるように説明してください。
```

回答は日本語として読めるが、内容には怪しい点が多かった。

特に怪しかった点:

- ローカルLLMはクラウド型と同じくらい大きい知能を持つ、という説明は雑
- ローカルLLMの方がより速く正確な答えを出せる、とは限らない
- クラウド型LLMでデバイス側のスペックが低いと遅くなる、という説明はやや不正確
- ローカルLLMはインターネットにつなげないと使えない、という説明は逆に近い

ここから分かったこと:

```text
LLMの回答は、文章として自然かどうかと、内容が正しいかどうかを分けて見る必要がある。
```

これはDay 5以降のモデル評価で重要になる。

### 評価質問は固定する

学習中の質問は、言い回しを変えて試してよい。
むしろ、どの聞き方でどう変わるかを見ることも学びになる。

一方で、モデル比較や精度確認では質問文を固定する必要がある。

理由:

- 質問文が変わると回答も変わる
- モデルが良くなったのか、質問が簡単だったのか分からなくなる
- 同じ質問、同じ素材、同じ観点で比べることで評価しやすくなる

今日の理解:

```text
学習中の質問: 言い回しを変えてOK
評価用の質問: eval/questions.md の文面をそのまま使う
```

## 今日出てきた重要用語

### LLM

Large Language Modelの略。
文章を入力すると、それに続く自然な文章や回答を生成する大規模言語モデル。

### ローカルLLM

クラウド上のサービスではなく、自分のPC上で動かすLLM。
インターネット接続や外部APIに依存しにくい一方で、PCの性能やメモリの影響を受ける。

### Ollama

ローカルPCでLLMを扱いやすくするための実行環境。
モデルの取得、管理、実行、API提供をまとめて扱える。

### TinySwallow

今回Ollamaで動かしている日本語向け小型LLMモデル。

### `ollama list`

Ollamaに登録されているモデル一覧を確認するコマンド。

### 評価質問

モデルの性能や特徴を比較するために固定して使う質問。
このチャレンジでは `eval/questions.md` を使う。

### 評価素材

資料をもとに回答できるか確認するための固定素材。
このチャレンジでは `eval/materials.md` を使う。

## まだ曖昧なこと

- `ollama run` でモデルに質問すると、裏側で何が起きているのか
- OllamaのCLI利用とAPI利用の違い
- GGUFやQ5_K_Mなど、モデル形式・量子化の細かい意味

## 自分の言葉でのまとめ

Ollamaは、ローカルPCでLLMを動かすための土台のようなもの。
モデルを取ってきたり、読み込んだり、ターミナルやAPIから使えるようにしたりする役割を持っている。

TinySwallowは、今回Ollama上で動かしている日本語向け小型LLMモデル。
ただし、LLM本人に「あなたは誰？」と聞いても正確なモデル名が返ってくるとは限らない。

また、LLMの回答は自然に見えても、内容が正しいとは限らない。
今後の評価では、自然さと正確さを分けて見る必要がある。

`eval/questions.md` はLLMの性能確認・比較のための固定質問集。
`eval/materials.md` は資料をもとに回答する精度を確認するための固定素材。
