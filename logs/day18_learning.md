# Day18 学習メモ

## 今日のテーマ

Markdown文書を300文字、500文字、1000文字で分割し、同じ質問でベクトル検索して、チャンクサイズによる検索結果の違いを比較した。

## 今日理解したこと

- チャンクは、長い文書を検索やLLMへの文脈注入で扱うための分割単位である。
- 2860文字の文書は、300文字で10個、500文字で6個、1000文字で3個に分かれた。
- 固定文字数の分割は簡単だが、単語、文、Markdownの見出しやコードの途中で切れることがある。
- 小さいチャンクは話題を絞りやすいが、必要な文脈が別チャンクへ分かれやすい。
- 大きいチャンクは文脈を保ちやすいが、複数の話題や無関係な情報が混ざりやすい。
- チャンクサイズに共通の正解はなく、文書の構造、質問の種類、取得件数などに合わせて評価する必要がある。
- コサイン類似度が最高のチャンクでも、回答に必要な情報が完整に含まれるとは限らない。
- チャンクの品質は、スコアだけでなく、質問に答えられる内容が含まれるか、文脈が切れていないか、無関係な情報が多すぎないかで確認する。

### 2つの質問で比較した結果

#### OpenAI互換APIとは何ですか？

- 300文字：1位は接続先の説明が中心で、直接的な定義は2位に入った。
- 500文字：1位に直接的な定義が入り、今回は比較的使いやすかった。ただし`OpenAI`が`O`と`penAI`に分断された。
- 1000文字：1位に定義が入ったが、OllamaやTinySwallowなどの関連話題も多く混ざった。

#### 会話履歴はどこに保存されますか？

- 300文字：1位だけで「モデル自身が記憶するのではなく、Pythonアプリが履歴を管理する」と分かり、今回は最も使いやすかった。
- 500文字：1位が「憶するのではなく」から始まり、「記憶」がチャンク境界で分断された。
- 1000文字：1位のスコアは`0.5557`で最も高かったが、文頭が分断され、関係のないツールの説明も多く含まれた。

1問目は500文字、2問目は300文字が比較的使いやすく、質問によって適したサイズが変わった。

## 今日出てきた重要用語

- チャンク：文書を分割した一つのまとまり
- チャンクサイズ：1チャンクに含める文字数やトークン数
- 固定文字数分割：文書の意味や構造ではなく、一定の文字数ごとに分割する方法
- 検索単位：Embeddingし、質問との類似度を比較する単位

## 実行したコマンドと、その意味

```bash
python src/chunk_text.py
```

`notes/day14_api_summary.md`を読み込み、300文字、500文字、1000文字で分割した。質問と各チャンクを`bge-m3`でEmbeddingし、コサイン類似度の上佉3件と各サイズの1位を表示した。

## まだ曖昧なこと

- Markdownの見出しや段落を保って分割する方法
- チャンクの前後を重複させるオーバーラップの適切な大きさ
- 複数の質問セットを使い、検索の品質を数値と内容の両方で評価する方法

## 今日のまとめ

チャンクを小さくすると検索対象の話題を絞りやすい反面、文脈が切れやすい。大きくすると文脈は残るが、無関係な話題も混ざりやすい。2つの質問で比較すると、使いやすいサイズが変わった。コサイン類似度の最高値だけではなく、取得した文章だけで質問に答えられるかも確認する必要がある。
