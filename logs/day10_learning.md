# Day 10 Learning Memo

## 今日のテーマ

`messages` に会話履歴を保存し、過去の発言をTinySwallowへ毎回渡す会話CLIを作る。

## 今日理解したこと

### `messages` とメッセージの関係

`messages` は、会話に含まれるすべてのメッセージを順番に入れるリストである。`messages` 自体がシステムメッセージになるわけではない。

リスト内の1件ごとに `role` と `content` があり、`role` がそのメッセージの種類、`content` が発言内容を表す。

```python
messages = [
    {
        "role": "system",
        "content": "日本語で簡潔に回答してください。",
    }
]
```

この例では、`messages` に入っている1件が、`role: "system"` によってシステムメッセージとして扱われる。

### 3種類の `role`

- `system`: AI全体の振る舞いや回答方針を指定する
- `user`: ユーザーが入力した発言を表す
- `assistant`: AIが返した回答を表す

会話を続けるには、ユーザーの発言だけでなく、AIの回答も `assistant` として履歴へ追加する必要がある。

### 会話履歴はPython側が毎回渡す

TinySwallowが会話を自動的に永続保存しているわけではない。Python側が `messages.append()` で発言を保存し、APIを呼び出すたびに `messages` 全体を渡している。

処理の流れは次のとおり。

1. ユーザーの入力を受け取る。
2. 入力を `role: "user"` として `messages` へ追加する。
3. `messages` 全体をTinySwallowへ送る。
4. 回答を `role: "assistant"` として `messages` へ追加する。
5. 次の入力でも、これまでの履歴をすべて送る。

### 履歴を渡すことと、正しく利用できることは別

「私の好きな食べ物はカレーです」と伝えた後、「私の好きな食べ物は何でしたか？」と質問した。

最初の実験では、回答内にカレーという言葉は現れたものの、「個人的なデータを記憶しません」と答え、質問へ直接回答できなかった。

`system` メッセージへ、過去の会話履歴を参照して直接回答するよう追記した後は、存在しない「日本語を学ぶことが好き」という情報を回答した。さらに別の実行では、最後に「ラーメンだと答えました」と、履歴にない内容を生成した。

確認用に送信直前の `messages` を表示すると、次の順序で正しく履歴が入っていた。

1. `system` の指示
2. カレーが好きだという `user` の発言
3. 最初の `assistant` の回答
4. 好きな食べ物を尋ねる2回目の `user` の発言

この切り分けにより、Pythonの履歴管理ではなく、TinySwallowの文脈理解や指示追従に弱さがあると判断できた。

短い履歴でも情報を取り違えたため、長い履歴の実験はここで切り上げた。履歴を長くすると、渡す情報量が増え、必要な情報を正しく扱う難しさも増える。

## 今日出てきた重要用語

- `messages`: APIへ渡すメッセージを時系列で保存するリスト
- `system`: AIの基本的な振る舞いを指定するメッセージ
- `user`: ユーザーの発言を表すメッセージ
- `assistant`: AIの回答を表すメッセージ
- 会話履歴: それまでのユーザーとAIの発言の並び
- コンテキスト: モデルが回答時に参照できる入力情報
- ハルシネーション: モデルが入力や事実にない内容をもっともらしく生成すること
- `while True`: 終了条件まで処理を繰り返すループ
- `break`: ループを終了する命令
- `append()`: リストの末尾へ要素を追加する処理

## まだ曖昧なこと

- モデルが短い会話履歴を正しく参照できなかった詳しい内部要因
- モデルごとの会話履歴の扱いやすさの違い
- コンテキスト長の上限に近づいたとき、どのように回答が変化するか
- 古い履歴の削除や要約など、長い会話を管理する具体的な方法

## 自分の言葉でのまとめ

`messages` は会話全体を入れる箱で、その中の各メッセージが `role` によって `system`、`user`、`assistant` に分かれる。

Python側では会話履歴を正しく送れていたが、履歴があってもTinySwallowが正しく理解して答えられるとは限らない。
