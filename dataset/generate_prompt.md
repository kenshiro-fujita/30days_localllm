# シンセティックデータ生成プロンプト

以下のプロンプト内にある `{話題}` を対象分野へ置き換え、1分野につき10件ずつ生成する。

対象分野：

- 開発仕様の検討
- マーケティング施策
- マネージャー定例
- 評価制度の検討
- 競合他社の動向調査報告
- 新規サービスの企画
- カスタマーサポートの改善
- 社内業務の効率化
- 採用と社員研修の計画
- 情報セキュリティ対策

## 生成プロンプト

あなたは、LLMの教師ありファインチューニングに使用するシンセティックデータの作成者です。

`{話題}`に関する架空の会議メモまたは業務メモと、その理想的な要約を10件作成してください。実在する企業の機密情報や個人情報は使用しないでください。

### 学習させたい振る舞い

会議メモや業務メモを、要点・決定事項・次の行動の3項目で簡潔に整理する振る舞いを学習させます。元メモにない情報を推測してはいけません。

### messagesの構成

各データは、次の3メッセージをこの順序で含めてください。

1. system
2. user
3. assistant

systemのcontentは、全件で次の文章に固定してください。

会議メモや業務メモを、要点・決定事項・次の行動の形式で簡潔に整理してください。メモにない情報は推測しないでください。

userのcontentには、架空の会議メモまたは業務メモを入れてください。

assistantのcontentは、必ず次の形式にしてください。

要点：
- 重要事項を3点以内

決定事項：
- 明確に決まったこと

次の行動：
- 担当者：実施する行動（期限）

### 要約ルール

- userに書かれている情報だけを使用してください。
- 要点は3点以内にしてください。
- 明示された期限、会議の目的や結論、具体的な数値や対象を優先してください。
- 主題と関係の薄い雑談や細部は省いてください。
- 必要な日付、金額、人数、担当者名は元メモどおり正確に残してください。
- 決定事項がない場合は「メモから確認できる決定事項はありません」と書いてください。
- 次の行動がない場合は「メモから確認できる次の行動はありません」と書いてください。
- 行動はあるが担当者が不明な場合は「担当者未定：〇〇を行う」と書いてください。
- 変更の経緯と最終決定が明記されている場合は、変更前後と理由を簡潔に残してください。
- 矛盾する記述のどちらが正しいか判断できない場合は、両方の記述と判断できないことを明示してください。

### 10件の内訳

- 短く断片的な箇条書き：3件
- 話し言葉、重複、短い脱線を含む文字起こし：3件
- 決定事項、担当者、期限などの一部が欠けたメモ：2件
- 変更の経緯が明記されたメモ：1件
- 解消できない矛盾を含むメモ：1件

### 多様性の条件

10件の間で、次の要素を変えてください。

- 会議の目的
- 登場人物と人数
- 決定事項の有無
- 担当者や期限の有無
- メモの長さと書き方
- 数値や日付
- 話し合いの進み具合

固有名詞や数値だけを置き換えた、実質的に同じデータを作らないでください。

### 出力形式

出力はJSONLだけにしてください。
1行につき1件のJSONオブジェクトを出力してください。
各オブジェクトの最上位キーは`messages`だけにしてください。
`messages`の値は、system、user、assistantの3件を含む配列にしてください。
JSON配列にはしないでください。
Markdownのコードブロック、前置き、説明、件数報告は出力しないでください。
content内の改行は`\n`としてエスケープし、各JSONオブジェクトを物理的な1行にしてください。
JSONの文字列にはダブルクォートを使用し、正しくパースできる形式にしてください。
